## Błąd wykryty podczas E2E i poprawka

Realny LIST wykrył problem niewidoczny w testach jednostkowych: n8n Data Table ignorował dynamiczny obiekt `filters` w nodzie `Read Page`, przez co odczyt pobierał ostatnie rekordy całej tabeli i domena odrzucała je kodem `COMM_PAGE_SCOPE_INVALID`.

Poprawka LIVE:

- rozdzielono paginację na `History Page`, `Read History Page` i `Read Changes Page`,
- filtry Data Table są jawne i statycznie zdefiniowane w grafie, a dynamiczne są tylko wartości,
- history: `DELIVERY + scope_id + id < cursor`, DESC,
- changes: `EVENT + scope_id + revision window + id > cursor`, ASC,
- początkowa granica historii została ograniczona do bezpiecznego PostgreSQL int32 `2147483647`,
- workflow po zmianie: 0 błędów walidacji.

Poprawka została utrwalona w repo jako `communication/finalize-api-candidate.mjs`, a test `test-v2-communication-pagination.cjs` blokuje powrót do dynamicznego obiektu filtrów.

## Zakres świadomie nieaktywowany

- NO_PROCESS — brak zatwierdzonego progu/ACK,
- FORGOTTEN_STOP — brak zatwierdzonej godziny i eskalacji,
- ATTENDANCE_CORRECTION — reguła automatyczna OFF do polityki ACK,
- WRONG_PROCESS / WORK_OUTSIDE_APP / NO_ACTIVITY — `es_verified=false`,
- polling komunikacji — `poll_seconds=null`; frontend korzysta ze spójnego worker-status i ręcznego odświeżenia zgodnie z aktualną konfiguracją.

## Brama odbioru
